# ADR 0012: Integración con ERP (post-MVP)

## Estado

Aceptado

## Contexto

El PRD supone "el ERP de la botica cuenta con infraestructura para soportar consultas en línea y
decrementos de stock concurrentes" (§7) y define un módulo de contingencia manual para caídas de la
API del ERP (RF-05). Sin embargo, no existe un contrato/API del ERP definido ni disponibilidad
garantizada para el MVP.

## Decisión

Dejar la **integración con el ERP central post-MVP**. En el MVP, el **módulo de stock manual**
(RF-05) es la fuente de verdad del inventario. Se diseña la capa de stock detrás de una interfaz
que permita enchufar el ERP después sin reescribir los consumidores.

## Alternativas consideradas

- **ERP en el MVP con circuit breaker + fallback** — cumple el supuesto literal del PRD, pero
  depende de una API de ERP hoy inexistente (contrato y disponibilidad no definidos), arriesgando el
  lanzamiento.

## Consecuencias

- Salida a producción sin depender de un tercero no disponible.
- Trade-off: no hay sincronización automática con el ERP en el MVP; el stock manual puede divergir
  del ERP real hasta que se implemente la integración.
